# M2–M6 + execução noturna: plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deixar o Agente MAW rodando sozinho esta noite (28/09/2026): testes de ponta a ponta na GUI real (a bancada do usuário primeiro), áudio medido pela placa interna, serviço de IA, sondas C++ e calibração, sem VB-Cable, com os resultados na bancada e no PDF.

**Architecture:** Cada trilha acrescenta um módulo novo com subcomando próprio na CLI (descobertos automaticamente pelo `cli.py`), para as trilhas andarem em paralelo sem conflito. Um script noturno roda as fases determinísticas fora do LLM e chama o `claude -p` só para as fases de julgamento. A MAW é instância única: tudo que abre a MAW de verdade roda em série.

**Tech Stack:** Python 3.13 (.venv), pywinauto (UIA), Win32 via ctypes (PostMessage, PrintWindow, SendInput), pyaudiowpatch (loopback WASAPI), numpy/soundfile, Python 3.10 (work/py310) para o serviço, MSBuild, Windows Task Scheduler, `claude -p`.

**Spec:** `docs/superpowers/specs/2026-09-27-agente-maw-design.md` (+ `privado/docs/2026-09-27-apendice-maw.md`). A bancada do usuário: página privada (URL em `privado/bancada/config.yaml`; coleção `testes`, 74 itens; resultados do agente em `resultados/<código>__windows__agente` com `{teste, plataforma, quem:"agente", estado: passou|problema|pulei, nota, em}`); cópia local em `work/bancada/`.

## Global Constraints

- Tudo das Global Constraints do M1 continua valendo (nunca escrever em `C:\Users\User\MAW*`, escrita pelo `sandbox`, público sem conhecimento interno da MAW, segredos nunca gravados, pt-BR, matriz sem célula vazia).
- **Sem VB-Cable (decisão do usuário, 28/09):** a saída da MAW é a placa interna; o agente captura o que ela toca por loopback WASAPI. Gravação com sinal conhecido na entrada não é possível: vira `pulei`/`nao_testavel` com motivo.
- **Instância única:** só um processo `MAW_APP.exe` de GUI por vez na máquina; todo cenário E2E roda em série e fecha a MAW ao terminar (ou mata e restaura o ambiente se ela travar).
- **`%APPDATA%\MAW` de teste:** antes de abrir a MAW, backup (fora do repo) → `MAW.settings` de teste (com os caminhos do Python e do ffmpeg do agente) → roda → restaura e confere → apaga o backup. Nunca com a MAW do usuário aberta.
- **Subagentes nunca executam binários da MAW nem instalam pacotes**: só as fases da CLI fazem isso.
- **Não roubar o computador durante o dia:** o driver usa UI Automation e mensagens de janela (sem mexer no cursor real) sempre que possível; teclado/mouse reais (SendInput) só com `MAW_AGENTE_ENTRADA_REAL=1`, que o script noturno liga.
- Commits: cada trilha adiciona só os próprios arquivos (`git add <arquivos>`); se `index.lock` existir, espera 2 s e tenta de novo (até 10 vezes). Cada trilha roda só os próprios testes; a suíte inteira roda na integração.
- Conhecimento específico da MAW (rótulos de menu, cenários, mapa da bancada, fixtures com o formato do projeto) vai para `privado/`; o público fica genérico.

## Review Focus

- MAW travada ou com diálogo modal inesperado no meio de um cenário → o cenário vira `problema` com screenshot, a MAW é morta, o ambiente é restaurado e o próximo cenário roda (teste no Task 3).
- Máquina sem saída de áudio / loopback indisponível → cenários de áudio viram `pulei` com motivo, sem quebrar a fase (teste no Task 5).
- Interrupção no meio da noite (queda de energia/reboot) → a próxima execução restaura o `%APPDATA%\MAW` antes de abrir a MAW (teste no Task 3, usa `appdata-sujo.json` do M1).
- Bancada inacessível (sem rede/artifact) → os resultados ficam no PDF e em `bancada.json` na pasta da sprint, e isso vira limitação declarada (Task 2).
- Permissão negada no `claude -p` noturno → a fase de julgamento registra a falha no estado e o script segue para o relatório com o que tem (Task 2).

### Task 3: Driver de GUI (`maw_agent/gui.py`)

**Files:** Create `maw_agent/gui.py`, `tests/test_gui.py` (unidade com janelas de teste do próprio Windows, ex. `notepad.exe`) e `tests/test_gui_maw.py` (`@pytest.mark.lento`, abre a MAW real).
